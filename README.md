# TimeSeriesChart

Переиспользуемый React-компонент для четырёх независимых календарных рядов: area, spline, line и bar. Визуальная модель основана на приложенном GIF: жёлтая область, зелёная плавная кривая, фиолетовая ломаная, синие столбцы и общий HTML-tooltip.

## Требования

- Node.js 20+
- npm 10+

## Запуск

```bash
npm install
npm run dev
```

Production build:

```bash
npm run build
```

## Публичный API

```ts
interface TimeSeriesPoint {
  readonly date: string;
  readonly value: number;
}

interface TimeSeriesChartProps {
  readonly area: readonly TimeSeriesPoint[];
  readonly spline: readonly TimeSeriesPoint[];
  readonly line: readonly TimeSeriesPoint[];
  readonly bar: readonly TimeSeriesPoint[];
}
```

`date` — валидная календарная дата строго в формате `YYYY-MM-DD`, от `0001-01-01` до `9999-12-31`. Время, Unix timestamp и часовой пояс не поддерживаются. Компонент не использует `Date` для календарной арифметики, поэтому локальная timezone и DST не сдвигают точки.

## Пример

```tsx
import { TimeSeriesChart, type TimeSeriesPoint } from './components/TimeSeriesChart';

const area: TimeSeriesPoint[] = [
  { date: '2026-06-10', value: 2.04 },
  { date: '2026-06-11', value: 25.85 },
];
const spline: TimeSeriesPoint[] = [
  { date: '2026-06-10', value: 610.78 },
  { date: '2026-06-12', value: 161.47 },
];
const line: TimeSeriesPoint[] = [
  { date: '2026-06-11', value: 30 },
  { date: '2026-06-13', value: 70 },
];
const bar: TimeSeriesPoint[] = [
  { date: '2026-06-10', value: 0.68 },
  { date: '2026-06-14', value: 0.71 },
];

export function Example() {
  return (
    <div style={{ width: '100%', aspectRatio: '2 / 1' }}>
      <TimeSeriesChart area={area} spline={spline} line={line} bar={bar} />
    </div>
  );
}
```

Компонент занимает размеры родительского контейнера. Для пропорций референса родитель использует `aspect-ratio: 2 / 1`.

Смена розового фона работает на всей demo-секции. Tooltip и подсветка точек остаются активны над и под рамкой графика, но скрываются при уходе в боковые поля слева или справа. Секция помечена атрибутом `data-chart-interaction-area`; без такого предка переиспользуемый `TimeSeriesChart` использует собственную рамку как interaction surface.

## Контракт данных

- Серии могут иметь разную длину и разные даты.
- Точки можно передавать несортированными; компонент сортирует копии и не меняет входные массивы.
- При повторе даты внутри серии используется последняя точка исходного массива.
- Отсутствующая дата означает отсутствие значения, а не ноль. Соседние существующие точки line/area/spline соединяются.
- `null`, `undefined`, `NaN`, бесконечные значения и некорректные даты не входят в TypeScript-контракт. Защитная runtime-нормализация пропускает такие точки.
- Пустая серия не рисуется. Если пусты все серии, компонент показывает «Нет данных».
- Отрицательные значения поддерживаются; область и столбцы строятся относительно нулевой линии.
- Расстояние по X пропорционально числу календарных дней между точками.

## Реализация

Apache ECharts 6.1 используется с Canvas renderer. Внешний API не экспортирует типы ECharts. Общий tooltip, поиск ближайшей даты, подсветка точек и позиционирование реализованы в React-слое, чтобы поведение не зависело от того, как ECharts сопоставляет разреженные серии.

Cost, CPA, ROI confirmed и Conversions используют отдельные скрытые Y-масштабы. Общий диапазон Cost/CPA делал все CPA-столбики ниже референса. Поэтому вертикальное положение разных метрик нельзя использовать для сравнения их абсолютных значений.

Area использует обычное spline-сглаживание ECharts без `smoothMonotone`: monotone-вариант создавал лишние локальные волны между возрастающими точками, которых нет в GIF.

Для очень малых значений CPA столбцы имеют минимальную визуальную высоту 2 px. Более высокий минимум не используется, поскольку он искажал наблюдаемую в GIF разницу между CPA 1.23 и остальными значениями. Исходные значения и tooltip не меняются.

## Производительность

В demo доступны проверочные наборы 100 и 1 000 точек на каждую серию. Компонент не вводит hard limit, не обрезает данные и не выполняет downsampling. Нормализация занимает `O(N log N)` из-за сортировки и `O(N)` дополнительной памяти; поиск ближайшей даты во время hover — `O(log U)`.

Для суммарного числа точек более 1 000 отключаются постоянные point markers и визуальная смена толщины spline на hover; для более 4 000 также отключается анимация. Это сохраняет исходные данные и tooltip, но убирает дорогие и уже неразличимые детали.

Фактическая проверка выполнена в dev-режиме и повторена на production build во встроенном Chromium-браузере Codex при размере plot 592 × 296 px; resize проверен на 320, 592 и доступной в viewport ширине 624 px:

| Размер | Результат |
| --- | --- |
| 100 × 4 | Обычно 83–174 ms до снятого браузером кадра; hover, общий tooltip и resize работают плавно |
| 1 000 × 4 | 183–402 ms; отрисовка и tooltip работают, постоянные markers отключены как слишком плотные |

Числа выше — приблизительное end-to-end время смены dataset до снятого браузером кадра, а не изолированный benchmark ECharts. Рекомендуемый размер для текущего визуального режима — до 1 000 точек на серию. Более крупные наборы считаются large dataset и не входят в регулярный QA-прогон.

Для существенно более плотных наборов возможны задержки при первой отрисовке и resize, а столбцы визуально сливаются. Возможные дальнейшие улучшения: согласованная агрегация/downsampling, агрегация или отключение bars, Canvas/WebGL renderer для больших данных и server-side aggregation.

## Известные ограничения

- Точное математическое сглаживание исходного графика неизвестно; используется monotone smooth ECharts.
- Алгоритм исходных Y-доменов не восстановим из GIF. Используется автоматическое округление диапазонов с отдельным запасом для семантики каждой линии.
- Touch-навигация, zoom/pan, интерактивная легенда и полноценная клавиатурная навигация не входят в текущую версию.
- Математическая форма spline, точная тень и палитровое смешивание GIF могут немного отличаться от исходной библиотеки; измеренные результаты Visual QA находятся в `VISUAL_QA.md`.
- Production build выдаёт предупреждение Vite о JS chunk около 648 kB (gzip около 220 kB); runtime warnings/errors в console не обнаружены.
