# TimeSeriesChart — Specification

Статус: спецификация утверждена; функциональная реализация и отдельный этап Visual QA выполнены 16.09.2026. Измеренные результаты и ограничения зафиксированы в `VISUAL_QA.md` и `README.md`.

## 1. Goal

Создать переиспользуемый React-компонент временных рядов с четырьмя независимыми сериями: area, spline, line, bar. Приоритет — соответствие GIF и простой типизированный API, не зависящий от библиотеки визуализации. Стек: React, TypeScript strict, Vite.

Спецификация служит контрактом реализации. Визуальные параметры остаются предметом отдельного этапа Visual QA.

## 4. Interaction Specification

Наблюдения:

- Один tooltip содержит дату и все четыре значения для выбранной даты. На одном X подсвечиваются несколько серий, а не только ближайшая по Y.
- В demo interaction surface по вертикали охватывает всю розовую секцию: над и под рамкой tooltip остаётся активным, а Y ограничивается ближайшим краем plot. По горизонтали interaction ограничен левой и правой границами графика; в боковых полях tooltip сразу скрывается.
- Tooltip меняет положение при движении курсора даже в пределах выбранной даты; бывает справа или слева, выше или ниже. Его прямоугольник в просмотренных кадрах остаётся внутри рамки графика, иногда прилегает к верхней/нижней границе.
- У выбранных точек видны цветные halo; вертикального crosshair нет. Курсор в записи имеет форму руки; источник такого курсора (график или родительская строка) неизвестен.
- После выхода курсора tooltip не всегда исчезает сразу: видны удержание и последующее затухание (около кадров 106–110); к кадру 112 tooltip отсутствует. Немедленное hide-on-leave не соответствует записи.
- Толщина spline и отдельные маркеры меняются между состояниями. Точные причины и длительности переходов по дискретным кадрам не установлены.

Предлагаемые правила для случаев, которых нет в GIF:

- Внутри plot выбирать ближайшую календарную дату из объединения серий по X; при равном расстоянии — более раннюю. В GIF даты совпадают между сериями: правило для независимых серий является дополнением.
- Показывать только exact-match значения выбранной даты. Отсутствующую серию пропускать, не интерполировать и не подставлять соседнее значение.
- Порядок area / bar / spline / line сохранять независимо от отсутствующих строк.
- Позиционировать tooltip относительно курсора с переключением стороны и ограничением рамкой; начальный отступ 16 px, затем визуальная сверка. Точную исходную формулу восстановить нельзя.
- Кандидат hide delay≈200 ms + fade≈150 ms; это параметры для настройки по записи, не точные измерения. При возврате курсора скрытие отменять.
- При resize/замене данных скрывать устаревший tooltip. При узком контейнере разрешить перенос названий, чтобы tooltip не выходил за пределы.
- Даты выводить как DD.MM.YYYY без преобразования через часовой пояс; денежные/ratio серии — 2 знака. Для дробных Conversions не терять дробную часть: до 2 знаков, без конечных нулей. Экстремальные числа — научная нотация. Эти расширения требуют согласования.
- Touch, keyboard navigation, zoom/pan и legend toggle в GIF не показаны; не добавлять без отдельного решения.

## 5. Public API

```ts
export interface TimeSeriesPoint {
  /** Calendar date in the strict YYYY-MM-DD format. */
  readonly date: string;
  readonly value: number;
}

export interface TimeSeriesChartProps {
  readonly area: readonly TimeSeriesPoint[];
  readonly spline: readonly TimeSeriesPoint[];
  readonly line: readonly TimeSeriesPoint[];
  readonly bar: readonly TimeSeriesPoint[];
}
```

```tsx
const area: TimeSeriesPoint[] = [
  { date: '2026-06-10', value: 2.04 },
  { date: '2026-06-11', value: 25.85 },
];
const spline: TimeSeriesPoint[] = [
  { date: '2026-06-10', value: 610.78 },
  { date: '2026-06-12', value: 161.47 },
];
const line: TimeSeriesPoint[] = [
  { date: '2026-06-11', value: 30 },
  { date: '2026-06-13', value: 70 },
];
const bar: TimeSeriesPoint[] = [
  { date: '2026-06-10', value: 0.68 },
  { date: '2026-06-14', value: 0.71 },
];

<div style={{ width: '100%', height: 360 }}>
  <TimeSeriesChart area={area} spline={spline} line={line} bar={bar} />
</div>
```

`readonly` позволяет принимать как обычные, так и неизменяемые массивы и фиксирует отсутствие мутаций со стороны компонента. Все четыре props обязательны; отсутствие серии представляется `[]`. Дополнительные props пока не нужны. Размер задаёт родительский контейнер; 360 px в примере — пример интеграции, а не измерение GIF. При обновлении данных потребитель передаёт новые массивы.

## 6. Input Data Contract

Предлагаемые решения контракта, не свойства, установленные по GIF:

| Вопрос | Контракт |
| --- | --- |
| Формат даты | Только строка `YYYY-MM-DD`: ровно четыре цифры года, две месяца и две дня. Поддерживаются валидные даты григорианского календаря в диапазоне `0001-01-01`…`9999-12-31` |
| Время и timezone | Не поддерживаются и не имеют семантики в API. ISO datetime, Unix timestamp, суффиксы `Z` и смещения `±HH:mm` не принимаются |
| Внутреннее представление | Дата преобразуется в целочисленный порядковый номер календарного дня без `Date.parse`, `new Date(string)` и локального часового пояса. Это исключает сдвиги из-за timezone и DST |
| value | Любое конечное JS number, включая 0 и отрицательные. Строки, NaN, ±Infinity не допускаются |
| Разная длина | Разрешена, включая нулевую |
| Совпадение дат | Не требуется. Ось X календарная и непрерывная: расстояние пропорционально количеству дней между датами, а не позиции точки в массиве |
| Сортировка | Не обязательна. Компонент сортирует копию каждой серии по календарной дате, исходники не меняет |
| Дубликаты | В пределах серии для одинаковой календарной даты побеждает последняя точка исходного массива. Одинаковые даты между разными сериями нормальны |
| Пропуски | Представляются отсутствием точки. В tooltip нет строки серии; ноль не подставляется |
| Линии через пропуски | Соседние существующие точки одной серии соединяются независимо от числа пропущенных календарных дней. Отсутствие даты не обозначает разрыв |
| null/undefined | Не входят в контракт ни для props, ни для точек/полей. Явные разрывы линий через null не поддерживаются |
| Некорректные runtime-данные | Защитная нормализация пропускает невалидные точки; не-массив обрабатывается как пустая серия. Это защита JS-интеграций, а не расширение TS API; не бросать исключение из render |
| Большие/малые числа | Не вводить произвольный диапазон для конечных value. Внутреннее масштабирование должно предотвращать overflow при вычислении домена; tooltip хранит исходное значение. Научная нотация — предлагаемый fallback для значений, не помещающихся в обычный формат |

Точность ограничена IEEE-754: различия меньше представимого шага восстановить нельзя. При огромном разбросе величин малые значения могут визуально совпадать с нулём. Внутреннее масштабирование не должно менять исходные значения tooltip или подписывать ось масштабированными величинами без обратного преобразования.

## 7. Edge Cases

- Одна пустая серия: не рисуется, не появляется в tooltip, не влияет на домен.
- Все серии пусты (в том числе после валидации): нейтральное состояние «Нет данных», без tooltip и невалидных осей. Внешний вид этого состояния — проектное решение.
- Единственная точка/единственная общая дата: расширить X-домен на один календарный день в обе стороны; показать точку line/spline/area и bar. У границ поддерживаемого диапазона расширять только в допустимую сторону.
- Константные значения и все нули: недегенеративный конечный Y-домен; нулевой bar не искусственно увеличивается, но доступен в tooltip.
- Отрицательные значения: bar направлен от нулевой baseline вниз; area заполняется относительно нуля; Y-домен содержит ноль при наличии area/bar. Это предлагаемая семантика: отрицательных значений в GIF нет.
- Нерегулярные интервалы: X пропорционален числу календарных дней. Предлагается центрировать bar на дате, ограничивать ширину по доступному расстоянию и сохранять крайние столбцы внутри plot area. Базовая ширина около 37 px при plot 592 px; для плотных нерегулярных данных ограничивать её расстоянием между соседними столбцами.
- Контейнер нулевого размера/скрытая вкладка: отложить инициализацию или resize до положительного размера. Не падать, не выдавать console warnings.
- Очень узкий контейнер: сохранять скрытые ticks, ограничивать tooltip доступной шириной. Минимальная ширина для визуального соответствия пока неизвестна.
- Обновление props, unmount и React StrictMode: удалять обработчики, ResizeObserver и экземпляр графика; не создавать утечки или дубли canvas.

## 8. Technical Approach

**Выбор: Apache ECharts 6.1, Canvas renderer, прямой адаптер внутри React-компонента.** Точное совпадение кривизны, динамической толщины линии и tooltip потребует визуальной проверки; при ограничениях штатного tooltip использовать собственный HTML-слой.

ECharts позволяет объединить line, smooth line, area через areaStyle и bar в одной системе координат. Есть axis-triggered tooltip и настройка стилей. Canvas выбран как разумный исходный вариант для рекомендуемого диапазона до 1 000 точек на серию, а не как гарантия скорости на больших наборах. HTML tooltip позволяет независимо настроить типографику, padding и тень. Публичные props преобразуются внутренним адаптером; типы ECharts не экспортируются.

Официальные источники:

- [Area chart](https://echarts.apache.org/handbook/en/how-to/chart-types/line/area-line/): areaStyle и заливка.
- [Smoothed line](https://apache.github.io/echarts-handbook/en/how-to/chart-types/line/smooth-line/): smooth line; название spline в нашем API не обещает конкретный математический сплайн.
- [Axis](https://echarts.apache.org/handbook/en/concepts/axis/): смешанные серии, стили осей, axis tooltip.
- [Canvas vs SVG](https://echarts.apache.org/handbook/en/best-practices/canvas-vs-svg/): выбор renderer и компромиссы.

Реализация адаптера:

1. Валидировать календарную дату и value, преобразовать дату в порядковый номер дня, дедуплицировать и отсортировать копии независимых серий; сохранить исходные строки `date` и значения. Не использовать JavaScript `Date` для календарной арифметики.
2. Построить отсортированное объединение календарных дней и lookup значений. Не добавлять нули или даты других серий в геометрию линий.
3. Настроить общую time axis и отдельные скрытые value axes для серий без stacking. Area — smooth line + fill; spline — smooth line; line — straight segments; bar — bar series. Шкалы должны воспроизвести восстановленные позиции demo. Для area/spline/line кандидат — автоматическое округление верхней границы до удобного шага с запасом, дающее на demo 75/750/120; для bar кандидат — совместимый с area диапазон, поскольку CPA остаётся у baseline. Это гипотеза: точные правила автошкалирования и привязка CPA не известны. Не зашивать восстановленные максимумы в компонент; согласовать алгоритм для произвольных данных и проверять его отдельно. Разные шкалы означают, что сравнивать абсолютные величины по высоте между сериями нельзя.
4. Проверить штатный axis tooltip на несовпадающих датах. Если он выбирает соседние значения разных серий, использовать выбор общего календарного дня бинарным поиском и собственный HTML tooltip по lookup. Это обеспечивает публичный контракт независимо от поведения библиотеки.
5. Размеры получать от контейнера через ResizeObserver, вызовы resize объединять на кадр. Освобождать ресурсы при unmount.
6. Визуальные параметры держать во внутренних именованных токенах; demoData вынести отдельно.

Альтернативы: собственный SVG даёт полный контроль, но требует самостоятельных scales, ticks, hit testing и кривых; это увеличивает объём реализации. Дополнительный React wrapper не нужен для небольшого жизненного цикла init/update/resize/dispose. Цена ECharts — размер зависимости, проверка сглаживания и необходимость контролировать shared tooltip для разреженных серий. Версии зависимостей выбрать и зафиксировать lockfile на этапе реализации.

## 9. Performance Expectations

### Recommended dataset size

Проверенный рекомендуемый диапазон — до 1 000 точек на серию. Для QA используются наборы 100 и 1 000 точек на серию.

Нет hard limit. Нормализация предполагает O(N log N) сортировку и O(N) дополнительную память, выбор общего календарного дня — O(log U), lookup четырёх значений — O(1), где N — всего точек, U — число уникальных дат. Это оценки алгоритма адаптера, не измеренная стоимость renderer.

### Large dataset behavior

Наборы больше 1 000 точек на серию считаются большими. Компонент не вводит hard limit и не обрезает их молча, но они исключены из регулярного performance-прогона; для них следует рассматривать aggregation/downsampling.

Будущие опции при доказанной необходимости: downsampling, агрегация с явной семантикой, отключение markers, другой режим rendering, WebGL. Canvas уже выбран базовым renderer. Такие оптимизации не входят в первый этап реализации.

### Performance-check

Проверить 100 и 1 000 точек **на каждую** из четырёх серий в production build. Использовать воспроизводимые данные, включая несовпадающие календарные даты. Наборы больше 1 000 точек считать large dataset и не включать в регулярный прогон.

На каждом размере: первичная отрисовка после передачи данных, обновление набора, движение курсора с tooltip, изменение ширины контейнера. После прогрева сделать несколько одинаковых прогонов; записать наблюдаемые задержки/long tasks и время до следующего отображённого кадра, оговорив ограничения методики. Не считать одно время setOption полным временем отрисовки. Проверить правильность значений tooltip и отсутствие console errors. В README честно описать среду, результаты и субъективную плавность отдельно от измерений. Отдельный benchmark-проект не требуется.

## 10. Assumptions

1. GIF предоставлен и изучен; геометрия и наблюдаемые состояния описаны выше. Исходные CSS, библиотека и конфигурация из изображения недоступны.
2. Разные вертикальные масштабы следуют из координат и значений; точный исходный алгоритм доменов не установлен. После визуальной сверки CPA отделён от масштаба Cost, поскольку общий диапазон систематически занижал высоту всех столбиков.
3. Выбран ECharts/Canvas; его smooth не гарантирует совпадение с исходным математическим spline. Кривизну и динамическую толщину сверить визуально, не называть алгоритм исходника установленным.
4. Строгий формат `YYYY-MM-DD`, календарная арифметика без timezone, exact-match для независимых серий, tie-break по ранней дате, last-wins дубликаты и соединение через пропуски — предлагаемый контракт, не наблюдения из GIF.
5. Компонент остаётся прозрачным. Demo-секция имеет фон `#FCEBEB` и целиком меняет его на `#FCE0E3`, когда курсор находится в любом месте секции.
6. Aspect ratio plot≈2:1 установлен для одного размера. Компонент заполняет размер родителя, а demo сохраняет 2:1; responsive поведение оригинала неизвестно.
7. Точный font family, исходные цвета/opacity, shadow, radius, hide delay, fade и формула позиционирования не восстанавливаются однозначно. В Visual Specification приведены измерения и кандидаты, которые не следует путать.
8. Дробные Conversions, отрицательные значения, пустые и одиночные серии, экстремальные числа и несовпадающие даты в GIF отсутствуют. Их поведение определено отдельным контрактом.
9. Touch, клавиатура, SSR и интерактивная легенда не показаны. Базовое доступное имя графика предусмотреть; полноценная доступная таблица/навигация требует отдельного решения.
10. Регулярная базовая проверка выполняется для 100/1 000 точек на серию. Рекомендуемый рабочий диапазон — до 1 000 точек на серию; это не hard limit. Более крупные наборы считаются large dataset и отдельно не прогоняются.
